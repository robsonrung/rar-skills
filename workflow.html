The design-gate router

judgment → lookup

Implementation and review

route by task shape

The shared routing rules select the right engineering practice. The model plan names the requested implementation and review routes and their receipt requirements before any worker starts.

implement-and-review
scope · one task

Completes one scoped task with the selected gates, lenses, practice skills, tests, and review. It produces evidence for the task acceptance contract.

applies coding-design-plan · design-gate · tdd · full-review when the task needs them
implement-tasks
scope · approved task queue

Uses bound queue inputs and exact approved routes. A read-only controller projects readiness; the conductor reserves calls before dispatch. Verify the combined state before releasing dependents. Commit-based integration needs commit authority.

calls implement-and-review for each approved task
models-consensus
scope · explicit request for more opinions

A user-invoked, read-only council with separate plan approval. Poll defaults to standard. Explicit lean is for low-risk questions; validated organizer evidence controls both approved judge calls. Routine reviews do not invoke it.

modes poll · debate · personas; lean uses per_call, not cmux

Verify and resume

captured evidence

Keep source identity, exact route controls, original logs, and independent review in immutable records. A worker success or prose pass alone does not establish readiness.

Select affected checks

The shared selector uses declared inputs and changed paths. Run affected and required fresh checks, retain matching captures, and assess any transfer explicitly. Unknown dependencies use whole-source scope.

One evidence packet

Validation, browser smoke, and review use the same captured check and observation contract. Export the current validation packet, obtain independent review, then verify readiness. Runtime gates remain separate.

Keep recovery limits

Reserve native and runner calls before dispatch. Reconcile uncertain completion before retrying. Resume retains role isolation and consumed budgets. Exhaustion stops only the affected work.

Claude capability cache entries bind current CLI, routing and preflight code, configuration, policy, launch context, model, and effort identity with a 24-hour limit. Each launch still checks authentication visibility and installation drift. Receipts, entitlement, quota, and request privacy remain current facts.

Optional discovery stays small: brainstorm batches up to five independent decisions after its territory gate; a prototype tests one question with one fixture or two useful alternatives. Prototype code remains disposable. Static checks do not prove model quality, latency, or cost savings.
