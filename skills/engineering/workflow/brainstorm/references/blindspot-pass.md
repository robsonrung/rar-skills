# Blindspot Pass

Use this pass when the user cannot evaluate a flagged territory. It turns unknown unknowns into decisions the user can make. It is a decision map, not a tutorial.

## Trigger

Run the territory gate when either signal appears:

1. The user says they lack working knowledge of the domain or system area.
2. Two consecutive replies show that the user cannot evaluate a question that needs domain judgment.

An undecided user does not trigger the pass. Continue the normal dialogue when the user can weigh the options.

## Territory gate

Before the first substantive question in that territory, ask one blocking question for that territory. Questions about the user's problem, users, evidence, and priorities continue normally.

Offer **Map the territory first** or **Continue with questions**. Do not repeat the gate for that territory. Declining the map does not authorize a default.

## Map the territory

Ground an in repository territory in its relevant code, configuration, and schemas. Ground an external territory in available sources. When a current source is unavailable, label the item as unverified model knowledge.

Show facts already settled by evidence with their source locator and revision. Do not present those facts as choices. Surface only decisions that need the user's judgment and hazards that constrain them. A hazard states its impact. It becomes a decision only when viable mitigations need a choice.

For each decision, state the decision in the user's vocabulary, why it matters here, the viable options, and the recommended answer. Order decisions by the effect on the outcome. Do not pad the map.

## Batch the decisions

After the gate, ask up to five independent decisions in one batch. When the user chose the map, use its decisions. Otherwise use grounded questions. Give each question its evidence, materiality, and recommended answer. A dependent decision waits for the next batch.

A recommended default may settle only a named nonmaterial uncertainty with the user's explicit authority. Record that authority and the assumption. Silence, a declined map, or an unanswered question is not approval. Keep every material decision open until the user settles it, delegates it, or explicitly defers it.

Record settled answers, assumptions, and hazards in the brainstorm decision summary. The pass runs once per territory and then returns to the normal dialogue.
