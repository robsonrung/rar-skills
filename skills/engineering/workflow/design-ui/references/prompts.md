# Adaptable prompts

Replace bracketed details with task context. Respect the user's scope and repository conventions.

## Image direction

Create an actual raster concept of [product and screen] for [audience] completing [task], at [viewport]. Include [exact content and sample data] in [state]. Follow [brand and constraints].

Direction [A] uses [composition], [type roles], [density], [palette], and [imagery] because [task reason]. Keep realistic text sizes, plausible spacing, and clear actions. Preserve requirements and data across concepts. Render a flat interface view suitable for implementation comparison. Do not substitute HTML, prose, or a device photograph for the requested image.

Make separate candidates whose layout and hierarchy differ meaningfully. Do not repeat the same composition with new colors.

## Interactive alternatives

Through `to-prototype`, build focused alternatives for [interaction] in the existing system's visual language. Keep task and content constant. Vary [behavior or information architecture]. Show each full size. Implement enough interaction and recovery to compare them. The chosen behavior is rebuilt in the product, not promoted.

## Neutral selection

Compare A and B for [user and task] under [constraints]. Choose A, B, or no clear winner. Cite visible evidence, tradeoffs, and uncertainty. Identify any requirement neither satisfies. Do not assume elaborate or unusual is better.

## Image translation

Use the selected image as visual direction. Identify hierarchy, grid, density, type roles, spacing, color, imagery, and component mapping. Separate visible facts from behavioral assumptions. Preserve identity while building editable UI, responsive layouts, keyboard behavior, and [states]. Explain material adaptations for usability or correctness.

## Rendered review

Inspect the brief, approved direction, screenshots, and live result. Exercise [journeys]. Identify visual discrepancies, task failures, responsive defects, and accessibility issues. Give exact location, evidence, impact, correction, and recheck. Separate blockers from preferences. Do not approve unverified behavior or infer full usability from screenshots.

## Focused refinement

Address [prioritized findings]. Preserve selected identity and verified behavior. Change the smallest coherent set of elements resolving the problem. Recapture matching states and compare with the best version. Retain the earlier version if the revision regresses the task or design.

## Preference memory

The user selected [option] and explicitly preferred [stated reason]. Update project design guidance with the decision and approved example. Keep inferred preferences separate. Apply this to related screens without generalizing to unrelated products.
