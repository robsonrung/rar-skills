# Research basis

Reviewed 17 November 2026.

Use this as provenance and optional deeper reading. Do not load every source during routine UI work. The workflow is an engineering synthesis of the sources below, not a claim that any single method wins universally.

## Evidence boundaries

Official guidance, author demonstrations, published procedures, and independent empirical evaluation provide different strengths of evidence. Popularity, attractive examples, repository stars, and model agreement do not establish superior usability.

The reviewed sources support explicit visual context and feedback from rendered interfaces. They do not establish that image generation before code always outperforms executable prototypes. Candidate counts, reviewer counts, and refinement budgets in this skill are practical defaults.

## Official sources

1. [OpenAI, Designing delightful frontends](https://developers.openai.com/blog/designing-delightful-frontends-with-gpt-5-4), 20 March 2026. Supports visual references, initial design constraints, generated visual options, real content, and browser inspection. Its model specific and marketing oriented advice should not become a universal app layout rule.

2. [OpenAI, Harness engineering](https://openai.com/index/harness-engineering/), 11 February 2026. Describes making live UI, screenshots, DOM, and runtime evidence available to agents. An internal engineering account, not a controlled UI design comparison.

3. [OpenAI, Building frontend UIs with Codex and Figma](https://developers.openai.com/blog/building-frontend-uis-with-codex-and-figma). Demonstrates preserving structured design context and moving between code and an editable canvas.

4. [OpenAI Academy, Design context and iteration](https://academy.openai.com/en/public/clubs/champions-ecqup/videos/design-context-and-iteration-with-codex-2026-07-09), posted 22 July 2026. Recommends reusable design guidance and concrete visual references. The page includes a transcript.

5. [Anthropic, Harness design for long running application development](https://www.anthropic.com/research/harness-design-long-running-apps), 24 March 2026. Explores separate generation and evaluation, calibrated visual criteria, and live browser criticism. Reports score drift risks, rising complexity, substantial iteration cost, and cases where an intermediate output was preferable.

6. [Anthropic, current frontend design skill](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md). Emphasizes decisions grounded in subject matter and deliberate visual craft. The live skill evolves, so old summaries of rigid font or color bans should not be treated as current universal rules.

7. [Claude Code, current best practices](https://code.claude.com/docs/en/best-practices). Distinguishes instructions from checks enforced by tools and recommends verifiable outcomes.

## Practitioners and videos

8. [Theo, Agents Sucked At UI (Until Today)](https://www.youtube.com/watch?v=xq0eB8vxeqk). Relevant sections concern visual councils, comparative references, and evaluator score instability. The original page verified the video title; detailed speech was available through a [timestamped transcript reproduction](https://www.usetranscribe.io/yt/xq0eB8vxeqk/t3-ui-improvement-ai). This was not a direct viewing or independent evaluation. Treat sponsor demonstrations separately.

9. [Theo, original tstack repository](https://github.com/t3dotgg/tstack). Documents council review across providers and its tool requirements. Supports the mechanism, not an empirical beauty guarantee.

10. [Dive Club with Meng To](https://www.youtube.com/watch?v=SznrOQYiahg), with [the host's original description](https://dive-club.beehiiv.com/p/purple-gradients), 1 July 2026. Confirms image generation for UI brainstorming and persistent design guidance. The description does not establish an optimal candidate count.

11. [Anshu, Dream Loop](https://github.com/achimala/dream-loop). Implements a generated target image, rendered implementation, separate critic, and refinement loop. Its original emphasis is impressive visual and 3D work. Its reported testing is narrow, so do not extrapolate to reliable enterprise UX.

12. [Emil Kowalski, prototype skill](https://aiforui.dev/skills/prototype), updated 15 September 2026. Produces working alternatives at full size with a switcher, supporting interaction exploration.

13. [Meng To, scoring workflow](https://github.com/MengTo/Skills/blob/main/agent-skills/workflow/workflow-score-to-target/SKILL.md). Documents anchored criteria, independent judging, evidence, and honest treatment of plateaus. Scores remain judgments.

14. [Paul Bakaus, Impeccable](https://github.com/pbakaus/impeccable). Separates product context, visual conventions, narrow refinement commands, critique, and audit. Its procedures are useful references; automatic style rules are not universal design truths.

15. [Anand Chowdhary, author controlled X crosspost](https://anandchowdhary.com/notes/2025/automated-design-review-with-claude/), 20 August 2025. Describes browser based automated design review and links the original post and workflow repository.

## Evaluation sources

16. [UI Bench paper](https://arxiv.org/html/2508.20410v3), September 2025 revision. Uses blinded expert pairwise comparisons for visual quality. Its study scope excludes accessibility, performance, and code quality; its historical tool ranking is not a current recommendation.

17. [Playwright visual comparisons](https://playwright.dev/docs/test-snapshots). Supports repeatable screenshot regression checks and documents environment sensitivity. Such checks do not judge beauty.

18. [W3C WCAG quick reference](https://www.w3.org/WAI/WCAG22/quickref/). Supplies actual accessibility requirements. A partial automated scan does not establish full conformance.

## Synthesis choices in this skill

1. Route by the unresolved question: appearance, interaction, or consistency with an existing system.
2. Explore distinct alternatives with constant tasks and content.
3. Preserve explicit user selection checkpoints and otherwise act within scope.
4. Translate the chosen direction into reusable decisions, editable UI, and defined states.
5. Compare actual renders and exercise real tasks independently of aesthetic scoring.
6. Use bounded iteration and retain the strongest verified checkpoint.
7. Learn from explicit user preferences without generalizing them beyond their context.
8. Validate workflow improvements on representative tasks before claiming broad superiority.
