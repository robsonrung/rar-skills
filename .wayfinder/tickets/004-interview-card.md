# The interview card

## Question

What does the one-question-per-card interview actually look like?

Build it as a static prototype against fake data — no server, no agent — so the visual decisions are settled cheaply and in isolation. To settle: how a question with option chips renders beside one wanting free text; how the "what's been settled" rail reads as it grows; how a recommended option is marked without burying the alternatives; what the card does while the agent is still composing the next question; and how it degrades on a narrow window.

Reuse the visual language of `docs/pipeline.html` and the existing board rather than inventing a third one.

Unblocked deliberately: this needs no protocol to be real, and settling the visuals early de-risks the ticket that wires it up.
